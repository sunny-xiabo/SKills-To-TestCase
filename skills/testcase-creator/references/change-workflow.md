# 增量变更工作流

适用于需求迭代：基于历史定稿做「新增 / 修改 / 废弃」，不整表重生成。

进入本流程前须已通过初始化检查。本流程与「全量新建」互斥；与全量阶段 2 的历史复用步骤默认互斥（增量以基线定稿为唯一历史源）。

## B1. 选择基线定稿

优先读取 `.testcase-assets/history/history-index.md`；若无索引则扫描 `history/*/2-用例定稿.md`。

```text
【增量变更 — 选择基线定稿】
  [1] <目录名>  （N 条，日期）
  [2] ...
  [0] 手动指定路径
```

读取：

- 必读：`2-用例定稿.md`
- 可选：同目录 `0-用例准备.md` 作上下文（用户要求时再读评审报告，默认不整份加载）

记录基线路径、用例总数、最大用例编号（用于续号）。

## B2. 输入本次变更

提示用户提供**本次变更**（不是完整需求），来源规则与全量阶段 1 相同（**A–I**，可组合设计稿与代码）：

- 代码变更优先：`scan_code_scope.py --git-root . --diff`（或 `--base`）限定范围后做影响分析  
- 仍须人确认变更分析，不得直接当定稿  

```text
【增量变更 — 变更输入】
请提供本次变更内容（文字 / 文件 / 链接 / 设计稿导出 / 代码路径或 git diff），说明改了什么规则、交互或范围。
```

解析后输出变更要点，保留多来源归属。不得用设计稿或代码覆盖未确认的文字变更。

## B3. 变更影响分析（确认门）

写入新运行目录：`.testcase-assets/history/<YYYYMMDD>_<HHMMSS>_<模块名>/0-变更分析.md`。

模块名来自基线测试对象或用户指定，清理文件系统非法字符。

```markdown
## 变更影响分析（请确认）

- **基线**：`history/<基线目录>/2-用例定稿.md`（N 条）
- **变更摘要**：...
- **影响模块/对象**：...
- **规则变化**：新增 / 修改 / 删除 / 未变
- **设计差异**（如有）：...
- **代码范围**（如有来源 I）：路径 / diff base …

### 建议动作预估
| 动作 | 数量（估） | 说明 |
|------|------------|------|
| 新增 | n | ... |
| 修改 | n | 对应基线 ID |
| 废弃 | n | 对应基线 ID，原因 |
| 保持 | n | 不展开全文，仅计数 |

[OK] 回复“确认”生成变更用例；指出错误则修正分析。
```

用户明确回复「确认」前，不得生成变更集。

## B4. 生成变更集并合并

### 编号规则

1. 读取基线最大主编号（`TC-080` / `TC-080a` 均计主号 80）
2. **新增**：从 `max+1` 连续分配，不重排旧 ID
3. **修改**：保持原 ID，禁止改号
4. **废弃**：ID 永不复用；不进入有效用例表
5. 前缀读取 `project.config.md` / `testcase-table-config.json` 的配置，默认 `TC`

### 输出文件

| 文件 | 内容 |
|------|------|
| `0-变更分析.md` | 影响分析 |
| `1-变更集.md` | 三类表：新增 / 修改 / 废弃 |
| `1-评审记要.md` | 合并后的**完整有效**用例表 |

### 变更集模板

```markdown
## 变更集

### 新增
| 用例ID | 所属模块 | 测试点 | ... | 场景类型 | 优先级 |
|--------|----------|--------|-----|----------|--------|

### 修改
| 用例ID | 所属模块 | 测试点 | ... | 场景类型 | 优先级 |
|--------|----------|--------|-----|----------|--------|
（输出完整新行，便于合并）

### 废弃
| 用例ID | 测试点 | 废弃原因 |
|--------|--------|----------|
```

备注列若存在：**必须留空**。过程信息写在变更分析或评审报告，不写备注。

### 合并规则（必须用脚本）

Agent **不得**手工拼合并全表。变更集写好后执行：

```bash
python3 .testcase-assets/scripts/merge_cases.py \
  --baseline <基线目录>/2-用例定稿.md \
  --changeset <运行目录>/1-变更集.md \
  --output <运行目录>/1-评审记要.md
```

脚本行为：

```text
result = baseline 有效表
for each 废弃 ID: 从 result 删除
for each 修改: 按同 ID 整行替换（ID 必须在基线且不在废弃列表）
for each 新增: 追加（ID 不得与有效基线冲突）
按用例 ID 稳定排序；备注列清空
```

校验失败（错号、撞号、废弃不存在等）时：修正变更集后重跑，**禁止** `--allow-warnings` 跳过除非用户明确要求。

合并成功后**必须**跑门禁（须出现 `[GATE OK] stage=merge`）：

```bash
python3 .testcase-assets/scripts/gate_stage.py --stage merge --run-dir <运行目录>
```

未过关不得进入评审或定稿。阶段回执中须粘贴 merge 与 gate 命令输出。

写入 `1-评审记要.md` 时：

1. 文首含脚本生成的变更合并摘要
2. 正文为合并后的完整有效用例表
3. 不得混入历轮评审过程

### 用户确认后

询问：

```text
A. 进入评审（阶段 4）
B. 跳过评审，直接定稿导出（阶段 5）
```

阶段 4/5 规则与全量相同；定稿文首须含：

```markdown
## 本轮变更摘要
- 模式：增量
- 基线：`history/<基线目录>/`
- 新增：TC-xxx, ...
- 修改：TC-xxx, ...
- 废弃：TC-xxx（原因）, ...
```

`history-index.md` 追加记录时标注 `mode: 增量` 与基线目录名。
